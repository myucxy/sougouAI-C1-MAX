# 验证记录与边界

## 当前发行记录

`verification/V0141/suite-exits.json` 保存 V0141 原先 23 组软件检查的退出结果；对应各功能的 JSON 在同目录。它们是已有结果的公开副本，并不表示本次整理又执行了全部 23 组原工程回归。

覆盖内容包括：四种播放模式、分页与隐藏文件、录音物理键、触屏、设置不断歌、原生音量绘制、半屏音量生命周期、小智模式、唤醒、内存失败处理、采音、PCM 边界、播放结束、录音恢复及升级准备等。

原工程中涉及旧版本对照包的完整回放与工具保留在工作区外历史归档，不随精简公开仓库分发。公开仓库没有伪造缺失的旧包或把历史测试标成当前重新执行。

## 整理后新增的检查

- 独立构建当前新增源码，保持固件 C／汇编源文件不变；本机产生的 OTA 与原 V0141 精确散列一致。
- 对公开 HTTP 响应解析、小智配置协议、WebSocket、Wi-Fi 配网协议和音频电平处理执行五组主机 C 测试，并启用 AddressSanitizer／UndefinedBehaviorSanitizer。
- 校验工具检查错误长度、错误散列、被强行跟踪的私有文件和外部符号链接等拒绝路径。
- 检查 Git 实际跟踪文件中没有原厂镜像、完整 OTA、设备身份配置、个人音频和已识别的凭据特征。
- 本地完整 OTA 检查容器、版本、RESC、受保护分区、3016 字节静态区以及 3072 字节预留。

实际结果保存在 `verification/repository-checks.json`。检查命令：

```sh
python3 scripts/run_checks.py
python3 scripts/check_public_tree.py --tracked
```

## 软件回放不能证明的事项

原生 ARM 指令回放可检查给定路径与输入；外部 Flash、USB、文件系统、播放器、UI、调度及复位等部分边界使用模型。通过结果不能证明整板启动、供电稳定、真实音频无爆音、长期实时性能、USB 枚举或断电恢复。

V0141 本轮没有刷写实体设备。保留原启动区和 Rec 不能保证刷坏后会自动回到旧系统；增强 Recovery 研究结果不能当作已交付功能。
