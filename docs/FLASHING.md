# 刷机说明与风险

本项目为 C208 固定样本固件的非官方实验性补丁。相同外观、型号文字或处理器不保证主板、屏幕、触摸、电源及 Flash 布局相同。当前镜像依赖已核对的二进制基线，不是通用 RK2108 固件。

## 在准备升级包之前

- 先导出录音和机内重要文件。音乐、录音、Wi-Fi 配置、小智身份文件不属于 8MiB SPI 系统镜像，需要分别处理。
- 保存本机原始 Flash 备份和校验值。有匹配编程器并具备拆机操作经验的用户，可以在首次刷机前先拆机备份原系统，方法与限制见下节。还应核实主系统无法启动时实际可用的回写通道；仅有 `.bin` 文件不能证明可以救机，另一台机器的备份也不能代替本机设备信息。
- 当前没有已验证通用的实体组合键进入 Rec 方法，底层 USB／MaskROM／编程器完整回写尚未完成本机实测。如果无法接受黑屏后可能需要拆机维修，应先停在源码和软件验证阶段。
- 建议电量至少 60%，保持供电稳定。原流程存在电量门槛，但越过门槛不代表断电安全。
- 预留至少 32MiB 机内空间供 OTA、拆包后的 FOTA 和工作余量；若还进行完整备份，要额外预留备份空间。

## 有编程器时，先拆机备份原系统

**如果有适配本机 Flash 的编程器，并具备拆机和芯片读写经验，建议在原系统仍正常、尚未刷入任何修改固件时，先拆机读取完整 SPI Flash，保存本机原系统镜像。** 这可为以后刷黑后通过编程器恢复提供原始数据；是否能够恢复，还取决于备份是否完整、芯片及主板是否正常，以及回写操作是否正确。

- 先断开 USB 和电池等供电，再按芯片及编程器的要求连接。核对 Flash 完整型号、容量、引脚方向、实际供电及逻辑电压，必要时使用匹配的电平适配器；不要仅凭芯片外形或“支持 SPI”就直接连接。
- 首次操作只读取，不擦除、不写入、不修改保护设置。在板夹读可能受到其他电路影响；若识别或读取不稳定，不要把不稳定的读取结果当作有效备份，应先排查连接和板级影响，必要时由有经验的维修人员拆焊读取。
- 独立读取至少两次，比较完整文件的长度和 SHA-256，结果应一致，再保留至少两份副本。重复读回一致只是必要检查，不单独证明镜像正确；仍需确认芯片识别、实际容量及镜像结构。本项目样本为 8MiB，其他主板应以实际芯片为准。
- 备份完整芯片内容，保留启动区、vendor、主系统、Recovery 和 DSP；记录芯片型号、读取日期和校验值。备份可能包含本机身份信息，放在本地私有位置，不上传 GitHub，也不要跨设备混用。
- 机内录音、音乐及位于机内存储中的配置另行导出，不能以 SPI 镜像代替文件备份。编程器读取的原始镜像也不能直接改名为 `SOGOUOTA.BIN` 进行 OTA。

**本项目尚未完成这台设备的编程器整片回写实测，也未提供已验证的接线图、电压参数或具体编程器型号。** 上述说明是备份准备建议，不代表已有“一定能救回”的恢复保证；具备编程器也不应跳过适配、读回校验和恢复通道核实。

## 文件与校验

V0141 `SOGOUOTA.BIN` 长度 8,388,624 字节。SHA-256 必须为：

```text
4a91383c0ae06ba16aa0772c42619ced8e4800b1d1d48dc9c75a106ee060d6f7
```

公开仓库不含完整固件。该文件在作者本机的 `_local/firmware/V0141/` 保存；外部用户需要自行取得适配且有权使用的镜像。不要从截图、改文件名、版本号或相同文件大小判断适配。

使用 `scripts/verify_release.py` 检查正式保留的 V0141。不要将 8MiB 原始镜像改名为 OTA，也不要将 8,388,624 字节的 OTA 直接交给 SPI 烧录器。

## 已知的正常投包流程

下列步骤仅适用于仍能正常启动、能够识别机内存储、且已确认适配与恢复条件的设备：

1. 暂停录音和播放，连接电脑并进入 USB 文件传输模式。
2. 把匹配的 `SOGOUOTA.BIN` 放在设备存储根目录，保持文件名，不放入录音子目录。
3. 核对设备上文件的长度与 SHA-256。使用小智时，身份文件必须属于本机；`scripts/stage_xiaozhi_official.py` 可在明确指定设备目录后准备 OTA 和首次身份，详情见隐私说明。
4. 安全推出设备盘，再断开 USB，让设备退出电脑存储模式。原程序会检测候选文件，检查条件后设置启动标志并进入 Rec 写入。
5. 过程中不要断电、强制复位或同时让电脑写盘。完成后核对设备显示版本，并检查开机、录音、录音回放、导出、MP3、音量、触摸、充电及 Wi-Fi。

仅复制文件不会证明已刷写；`SOGOUOTA.BIN` 消失也不能证明升级成功。原程序可能在拒绝包或清理时删除文件。电脑挂载目录里的文件版本不能证明当前 SPI 正在运行的版本。

V0141 的本地版本比较门槛已被移除，允许同版本／低版本候选进入该路径；这增加了误投旧包的可能。不要依赖版本号阻止错误刷写，也不要据此认为任意降级都安全。

## 黑屏时

黑屏可能来自显示初始化、堆不足、线程栈、对象生命周期、地址错误或启动故障。保持静态 RAM 预留不变只能减少一类问题。应区分电脑是否仍识别、是否有串口输出、能否关机和供电状态，保留日志及最近固件的散列。

不要为了强制恢复去破坏主系统校验、擦除启动区、随意短接测试点或反复写入未知固件。目前保留 Rec，只证明该恢复镜像尚未被当前包改动；不证明自动回退或独立手动救机已经验证。

详细的待实现恢复方案见 `RECOVERY.md`。本项目没有对用户设备执行升级，也没有对整机故障恢复作保证。
